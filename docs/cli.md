# CLI reference

Every `vapi` command, its options and its exit codes. Install the CLI with `npm i -g vapi-network`, or prefix a command with `npx vapi-network`.

The code installer and Claude Code/Codex launchers below are available since 0.12.0. Tasks V2 is live on Base mainnet (chain 8453). Solidproof signed off the audit on 23 November 2026. The platform fee is 0% at launch; the owner Safe may raise it to at most 20%. Each task and each pool budget is capped at 5,000 USDC. Disputes cost 10% of the milestone, with a 20 USDC minimum and 500 USDC maximum. See [Tasks](./tasks.md) for Guardian requirements and deployment pins.

Most commands accept `--json` and write one success or error value to stdout.
The Claude Code and Codex launchers are interactive and reject that flag.
Task watch and a partially completed scope-signing flow can emit newline-delimited
JSON; delivery emits one result after chain success. See [Task commands](./tasks.md#cli). Exit codes are
`0` for success, `1` for an operational failure, and `2` for invalid usage or
an announced preview-only command.
Solana listings remain searchable. Inspecting or paying one returns
`unsupported_network` (CLI exit `1`); vault payments on Solana arrive in a later release.
Inspect shows the registry’s last observed quote; pay fetches a fresh quote before signing.
Hosted search hides listings in outage unless `--include-outage` is set.
API hits can include health and cheaper or healthier alternatives; inspect can
include response schemas and an example request. Search, inspect and pay JSON
results include zero to four next-action hints.

Protected-vault access and legacy secret-store commands are documented in the [wallet guide](./wallets.md).

Every wallet command takes `--account <name>`, falls back to `VAPI_WALLET`, then the default from `vapi accounts use`; `--wallet <name>` is deprecated and still accepted.

Task exit codes are `0` ok, `1` error or invalid usage, `2` policy refusal, and `3` approval needed in non-interactive mode. Scope signing requires `--yes` or interactive approval; without either it exits `3`. A policy refusal at exit `2` has JSON `ok:false` with `reason: "policy.perTask"` or `reason: "policy.perDay"`. Invalid usage exits `1` with `{ok:false,error:{code:"usage_error",message}}`. Run `vapi task --help` for details. V2 chain operations use the verified Base mainnet pins without overrides. Other chains, including Base Sepolia, need an explicit complete V2 deployment override. The client verifies factory, clone and resolver state through the trusted RPC before signing. It records pending operations under `VAPI_HOME` for recovery. Funding and dispute fees apply local per-task and daily caps before signing; `--yes` grants approval without bypassing caps. Legacy V1 scope flows retain their local scope binding and counterparty checks. See [task security and recovery](./tasks.md).

Posting without `--fund` moves no money. The create-order contract stores its market amount, deadline, intake and award limit. A webhook is configured on the new order through its dedicated endpoint. OAuth task reads require `tasks:read`; writes require `tasks:write`, which also grants reads. See [Task commands](./tasks.md#cli).

Every Railway destroy requires exit zero, including launch-failure, signal, persistence-rollback, terminal-status and direct-stop cleanup, even when failure text says “not found.” Stderr warnings on exit zero are harmless. Failed launch cleanup retains an identified orphaned sidecar; failed terminal-status cleanup stays `running` and retries on refresh. A failed starting or running stop becomes `unknown` and keeps blocking dissolution. Verify destruction in the original Railway project/environment, then use `vapi swarm forget-run <name> <runId> --confirm-destroyed` if a successful destroy is unavailable.

```sh
vapi sweep <your-address> --asset eth
```
