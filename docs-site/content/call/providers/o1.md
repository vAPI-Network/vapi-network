o1 Launchpad creates fixed-supply tokens with permanently locked Uniswap v4 liquidity on Base, Robinhood, Monad, Arc, BSC and X Layer. Its public API lists launches, trades, holders and wallet activity, quotes swaps, and prepares unsigned wallet transactions. On Call, vAPI hosts an x402 layer in front of that API. You pay per call in USDC on Base, straight to o1's wallet, with no o1 account and no API key.

o1 also offers the same API directly at `api.launch.o1.exchange` with a free API key from [o1 Developers](https://launch.o1.exchange/developers). Call is the route for an agent that has a wallet and no key.

## How a call is paid

1. You send a `POST` with a JSON body to `api.vapinetwork.ai/shim/o1/<endpoint>`.
2. vAPI answers 402 with the endpoint's offer, for example $0.002 in USDC on Base to o1's wallet.
3. Your client or browser wallet checks the offer against your limits and signs the payment.
4. vAPI validates the body, forwards the request to o1's API, and settles the payment only when o1 returns a usable answer.
5. The `vapi` client writes a receipt; the console shows the settlement reference.

The payment goes to o1's wallet in full. vAPI does not sign for you and keeps no share. The listing carries the badge "Provider failures aren't charged": invalid input, o1 errors (401, 403, 429, 5xx), timeouts and throttling end the call without settlement. A valid request that o1 answers with 400, 404 or 422 is settled, because o1 did the work.

## Endpoints

The listing has 16 endpoints. Every endpoint takes a `POST` with a JSON body; vAPI maps it to o1's own `GET` or `POST` route.

| Endpoint              | What it returns                                                                                            | Price  |
| --------------------- | ---------------------------------------------------------------------------------------------------------- | ------ |
| `config`              | Launchpad configuration for one chain: suites, contracts, quote assets                                     | $0.01  |
| `tokens`              | Tracked launch tokens, sorted by `newest`, `oldest`, `trending`, `liquidity`, `market_cap` or `volume_24h` | $0.002 |
| `tokens-search`       | Tokens matching `q`: address, name, symbol, creator, pool or launch transaction                            | $0.002 |
| `token`               | One launch token's details                                                                                 | $0.002 |
| `token-trades`        | Trades of one launch token                                                                                 | $0.003 |
| `token-holders`       | Holders of one launch token, up to 50 per page                                                             | $0.01  |
| `token-announcements` | Creator announcements for one launch token                                                                 | $0.002 |
| `creator-tokens`      | Launches created by one wallet                                                                             | $0.002 |
| `wallet`              | Launchpad overview of one wallet                                                                           | $0.002 |
| `wallet-activity`     | Public launchpad activity of one wallet                                                                    | $0.003 |
| `wallet-fee-claims`   | Fee positions of one wallet                                                                                | $0.003 |
| `transaction`         | Indexed status of one transaction                                                                          | $0.001 |
| `swap-quote`          | A live exact-input swap quote with a signed `quote_id`                                                     | $0.005 |
| `swap-prepare`        | An unsigned swap transaction from a quote                                                                  | $0.01  |
| `launch-prepare`      | An unsigned launch transaction plan                                                                        | $0.05  |
| `fee-claims-prepare`  | Unsigned fee-claim transactions, up to 10 claims                                                           | $0.015 |

Every body needs `chain_id`, except `swap-prepare`. Use `8453` for Base, `4663` for Robinhood, `143` for Monad, `5042` for Arc, `56` for BSC or `196` for X Layer. The chain you query does not change how you pay: payment is always USDC on Base.

The token endpoints take `token_address`; the wallet and creator endpoints take `address`; `transaction` takes `tx_hash`. List endpoints accept `limit` (1 to 25) and the `cursor` from the previous page's `pagination.next_cursor`. Bodies are strict: an unknown field is refused before payment settles. The 402 offer carries each endpoint's full input schema and an example body. Check an endpoint's offer for free:

vapi check https://api.vapinetwork.ai/shim/o1/tokens --method POST

## Prepared transactions

`swap-prepare`, `launch-prepare` and `fee-claims-prepare` return unsigned transactions. Your own wallet signs and sends them, and pays the gas on the chain you chose. vAPI and o1 never hold your keys or sign for you. The x402 payment buys the prepared transaction, not the trade.

A swap takes two paid calls. `swap-quote` returns a `quote_id` that expires after two minutes, the expected and minimum output, and an `issues` list. Fix every blocking issue, complete any approval step, then send the `quote_id` to `swap-prepare` with the same `wallet`. Submit the returned transaction unchanged from that wallet.

```bash
vapi pay o1-launchpad \
  --endpoint swap-quote \
  --method POST \
  --content-type application/json \
  --body '{"chain_id":8453,"wallet":"0x39733BD6670B1d0EA1ec081F8B2137663Bc2d510","token_address":"0xb2000000000000000000004c27f6523082f41d01","side":"buy","amount_in_raw":"1000000000000000","slippage_bps":100}' \
  --max 0.01
```

This wallet held no ETH on Base, so the quote came back with a blocking issue and no steps. The call still settled $0.005, because o1 answered. The `body.data` from that run, shortened:

```json
{
  "quote_id": "eyJleHBpcmVzQXQiOjE3OTI1MDY0Mjk1MjEsInBheWxvYWQiOnsiYW1vdW50…",
  "expires_at": "2026-10-20T14:27:09.521Z",
  "chain_id": 8453,
  "amount_in_raw": "1000000000000000",
  "expected_out_raw": "199251581510776989652",
  "minimum_out_raw": "197259065695669219755",
  "issues": [
    {
      "code": "insufficient_input_balance",
      "severity": "blocking",

```

`amount_in_raw` is in the input asset's base units: `1000000000000000` is 0.001 ETH. `slippage_bps` of `100` allows 1% below the expected output. `launch-prepare` accepts up to 3 MiB so the body can carry the token image as base64; every other endpoint accepts up to 64 KiB.

## Before you start

- For the console: a browser wallet with a little USDC on Base.
- For the CLI, SDK or MCP: Node.js 22 or later and the `vapi` wallet from the [Quickstart](/call/quickstart/), funded with a few dollars of USDC on Base. You do not need ETH for the x402 payment.
- To send a prepared transaction: the native gas token on the chain you chose, in the wallet that signs.

## In the console

1. Open [api.vapinetwork.ai/call/o1-launchpad](https://api.vapinetwork.ai/call/o1-launchpad) and choose an endpoint, for example `tokens`.
2. Under **Request input**, choose **JSON** and enter the body, for example `{"chain_id": 8453, "sort": "trending", "limit": 5}` for `tokens`.
3. Choose **Check live price**. The quote shows $0.002, Base, and o1's wallet as the payee.
4. Connect your wallet if you have not, choose **Pay 0.002 USDC and call**, and sign the authorization your wallet shows.
5. Choose **View result** to read the JSON response and its settlement reference.

## With the CLI

List the three trending launches on Base:

```bash
vapi pay o1-launchpad \
  --endpoint tokens \
  --method POST \
  --content-type application/json \
  --body '{"chain_id":8453,"sort":"trending","limit":3}' \
  --max 0.01
```

`--max` is the most you agree to pay for this call. The client refuses to sign if the live offer is higher. The result is JSON with `status`, `body` (o1's response) and `payment`. From the run above, shortened:

## With the SDK

```ts
import { createVapiClient } from "vapi-network";

const vapi = await createVapiClient({ account: "main" });

const result = await vapi.call.pay({
  id: "o1-launchpad",
  endpoint: "token",
  method: "POST",
  contentType: "application/json",
  body: { chain_id: 8453, token_address: "0xb200000000000000000000cfbdf64a8706a94a01" },
  maxPriceUsd: 0.01,
  expectedPayTo: "0x1cAa1962428382106Eb3f29B9719bdF797621C90",
});

console.log(result.body.data.token);
```

`endpoint` is required for this listing because it has several endpoints. `expectedPayTo` makes the client refuse an offer that pays any other address. The SDK applies the account's caps and writes the same receipts as the CLI.

## From an agent on MCP

Install the local MCP server once ([Quickstart, MCP tab](/call/quickstart/)):

```bash
vapi mcp install claude-desktop    # or: claude-code, cursor, codex
```

Then ask, for example:

> Use o1 Launchpad on vAPI to list the five trending launches on Base with their market caps.

> Use o1 Launchpad on vAPI to show the latest trades and top holders of token 0xb200000000000000000000cfbdf64a8706a94a01 on Base.

> Use o1 Launchpad on vAPI to list the launches created by wallet 0x19328a5331635eb00f4d51b2a504e3537b605249 on Base.

> Use o1 Launchpad on vAPI to quote a buy of 0.001 ETH of token 0xb2000000000000000000004c27f6523082f41d01 on Base for my wallet, and tell me about any blocking issues.

The agent calls `call.search` to find the listing, `call.inspect` with the endpoint name to read its offer, and `call.pay` with `maxPriceUsd` to run it. The account's caps bound what it can spend. A prepared transaction comes back unsigned; the agent cannot send it without a wallet that holds gas on that chain.

## Price

Each endpoint has a fixed price, listed in the Endpoints table, as of this page's check date. There is no vAPI fee. The live 402 offer is the price; your client compares it with `--max`, `maxPriceUsd` and your caps before signing.

## Limits and errors

| Problem                                                    | What to do                                                                                                                                                                                                                                       |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| The client refuses to sign                                 | The live offer is above `--max` or `maxPriceUsd`, or above your account caps. Raise the limit, or check the offer with `vapi check`.                                                                                                             |
| `ambiguous_default` or "has 16 distinct payable endpoints" | Name an endpoint with `--endpoint` in the CLI or `endpoint` in the SDK.                                                                                                                                                                          |
| "returned HTTP 400 without decisive settlement evidence"   | vAPI refused the body: a wrong `chain_id`, an unknown field, or a malformed address. It does not settle. Run `vapi pay --resume <receipt-id>` after the authorization expires to confirm, then fix the body against the schema in the 402 offer. |
| 409 `payment_in_use`                                       | The same signed payment is already in flight. Wait for the first call to finish; do not resend the same payment.                                                                                                                                 |
| 429 `payer_throttled`                                      | Your wallet passed 30 requests a minute or its daily allowance of o1 calls. Wait for the `Retry-After` time. Throttled calls are not settled.                                                                                                    |
| 503 `partner_unavailable`                                  | All Call buyers share one o1 API allowance, and it is used up for now. Wait for the `Retry-After` time. The call is not settled.                                                                                                                 |
| A quote has `issues` with `severity: blocking`             | The signing wallet lacks balance or approval on that chain. Fund it or complete the approval step, then quote again.                                                                                                                             |
| `swap-prepare` fails after a delay                         | The `quote_id` lasts two minutes. Request a new quote.                                                                                                                                                                                           |
| A response is lost after you paid                          | Run `vapi pay --resume <receipt-id>`. It reads the chain and tells you whether the payment settled.                                                                                                                                              |
| Not enough USDC                                            | Run `vapi balance`, then `vapi fund`.                                                                                                                                                                                                            |

`launch-prepare` has its own limit of 3 calls a minute and 100 a day, shared by all Call buyers.
